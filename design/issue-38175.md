## Shared mechanism (as implemented in this repo)

- `vllm/model_executor/models/interfaces.py`: `SupportsEncoderCudaGraph` protocol. A model
  opts in by inheriting it and implementing `get_encoder_cudagraph_config`,
  `get_input_modality`, `get_encoder_cudagraph_budget_range`,
  `get_encoder_cudagraph_item_specs`, `select_encoder_cudagraph_items`,
  `prepare_encoder_cudagraph_capture_inputs`, `prepare_encoder_cudagraph_replay_buffers`,
  `encoder_cudagraph_forward`, and `encoder_eager_forward`. Optional hooks such as
  `postprocess_encoder_output` and `get_max_frames_per_video` have defaults.
- `vllm/v1/worker/encoder_cudagraph.py`: `EncoderCudaGraphManager` is model-agnostic. It
  captures one graph per token budget (largest first, sharing buffers across budgets),
  replays the smallest budget that fits a batch once per path, and falls back to eager
  otherwise. Enabled by `compilation_config.cudagraph_mm_encoder` (default `False`).
- `vllm/v1/worker/encoder_cudagraph_defs.py`: `EncoderCudaGraphConfig`, `EncoderItemSpec`,
  `EncoderCudaGraphCaptureInputs`, `EncoderCudaGraphReplayBuffers`.
- Docs: `docs/design/cuda_graphs_multimodal.md` (supported-model table).
- Reference integrations: InternVL (`internvl.py`, fixed 448x448 tiles, no rotary),
  Qwen3-VL (grid/cu_seqlens metadata), Qwen2-VL and Qwen2.5-VL (rotary, windowed attention).

## Chosen model: Skywork-R1V

Skywork-R1V reuses InternVL's pieces: `InternVisionModel` from `intern_vit.py`, the
`BaseInternVLMultiModalProcessor` / processing info / dummy builder, and the same vision
path in `extract_feature`:

1. `vision_model(pixel_values)` (plain ViT, no rotary, no cu_seqlens, no windowing)
2. drop the CLS token, reshape to a square grid
3. `pixel_shuffle` with `downsample_ratio`
4. `mlp1` (LayerNorm, Linear, GELU, Linear)

Every tile is a fixed `image_size x image_size` input, so the only graph-recorded buffer
is `pixel_values_flat` with shape `[num_tiles, 3, S, S]`. Each image contributes
`image_num_patches[i]` tiles and `num_image_token` output tokens per tile. This matches
InternVL's integration, and the vision tower needs no dynamic-shape metadata.

Dynamic shapes are handled by the manager through budgets, not by the model. Each batch is
padded to the smallest captured budget, and the model only needs to slice per-item tiles out
of the flat buffer (`select_encoder_cudagraph_items`).

## Proposed change (implemented, image path only)

File: `vllm/model_executor/models/skyworkr1v.py`

- Import `SupportsEncoderCudaGraph` and add it to the base list of `SkyworkR1VChatModel`.
- `get_encoder_cudagraph_config`: `modalities=["image"]`, `buffer_keys=["pixel_values_flat"]`,
  `out_hidden_size=text_config.hidden_size`. Skywork has no video inputs, so there is no
  video branch (InternVL's video branch is not copied).
- `get_input_modality`: always `"image"`.
- `get_encoder_cudagraph_budget_range`: min = `num_image_token` (one tile), max =
  `min(max_num_batched_tokens, max_model_len)`, as in InternVL.
- `get_encoder_cudagraph_item_specs` / `select_encoder_cudagraph_items`: per-item tile counts
  from `image_num_patches`, with the same cumulative-offset slicing as InternVL.
- `prepare_encoder_cudagraph_capture_inputs`: dummy `randn` tiles sized
  `max(token_budget // num_image_token, 1)`, at the image size used in `__init__`
  (`force_image_size or vision_config.image_size`).
- `prepare_encoder_cudagraph_replay_buffers`, `encoder_cudagraph_forward`,
  `encoder_eager_forward`: pass `pixel_values_flat` through `extract_feature` and reshape to
  `[-1, text_hidden_size]`.

Nothing changes when `cudagraph_mm_encoder` is off. `embed_multimodal` and `forward` are untouched.

File: `docs/design/cuda_graphs_multimodal.md`: one row added to the supported-model table
(`SkyworkR1VChatModel`, image only, no video, no multi-path).

## Test plan


1. Syntax and lint: `python3 -m py_compile` and `ruff format` / `ruff check` on the edited
   file (done, passed).
2. Unit parity (CPU-free logic where possible): `select_encoder_cudagraph_items` with
   mixed tile counts returns the same tensors as slicing by hand; item specs have
   `output_tokens = tiles * num_image_token`.
3. GPU parity: add `"skywork_r1v"` to `tests/models/multimodal/generation/test_vit_cudagraph.py`
   (image case, comparing `cudagraph_mm_encoder` on vs. off). Output embeddings must match
   eager exactly, as in the InternVL and Qwen3-VL cases.
4. Registry: the existing `Skywork/Skywork-R1V-38B` entry in `tests/models/registry.py`
   needs multiple GPUs; a dummy-weights or reduced-layer config is preferable for CI.
5. Benchmark: encoder latency and TTFT with and without graphs, 1-tile and multi-tile images,
   on an available NVIDIA GPU. No numbers are claimed here.
6. Docs build check for the new table row.

## Risks

- The processor's real tile size must equal the capture size. Capture uses
  `force_image_size or vision_config.image_size`, the same as `__init__`. A mismatch would
  make replay read a differently shaped input. Verify with a real Skywork processor run.
- `Skywork/Skywork-R1V-38B` is large, so GPU validation needs a multi-GPU node.
- `Skywork`'s HF class does not call `post_init()` and is loaded with
  `trust_remote_code` (see the registry note), so the new base class must not change
  weight loading. `load_weights` is untouched.
- AWQ path (`_patch_quant_config`) only affects quant config, not the graph path.
- Padding: a batch with fewer tiles than the budget runs with zero-filled tiles. These
  rows are sliced away by the per-item offsets. Same behavior as InternVL, but unverified
  for Skywork's `pixel_shuffle` with `ps_version` "v2".
- Scope is image only. Video, multi-path, and rotary/windowed towers are out of scope.
