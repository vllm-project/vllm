# Issue #66248: invalid `SamplingParams.structured_outputs` type raises AttributeError

## Summary

Passing a value other than `StructuredOutputsParams` or `None` as
`SamplingParams.structured_outputs` (for example the string `"json"`) is
accepted at construction. It then fails inside request validation with
`AttributeError: 'str' object has no attribute '_backend'`. The fix is a type
guard that raises `VLLMValidationError` before any attribute access.

## Open PRs

- #66256, "[Bugfix] Reject a structured_outputs value that is not StructuredOutputsParams".
  It is open and returned by the `gh search prs` for 66248. Per the issue
  comment, it rejects non-`StructuredOutputsParams` values at construction for
  both `SamplingParams` and `BeamSearchParams`. This branch targets the same
  bug at validation time, so the two overlap. The construction-time check is
  the more complete option; this branch's guard is a fallback at `verify()`.
  Reviewers should pick one.

## Code path (upstream/main 176a74c8e0)

- `vllm/sampling_params.py:411` declares
  `structured_outputs: StructuredOutputsParams | None = None`.
- `SamplingParams.__post_init__` / `from_optional` does no type check on this
  field, so `"json"` is stored as-is.
- The request path calls `params.verify(...)` from
  `vllm/v1/engine/input_processor.py:149` (generation tasks).
- `SamplingParams.verify` (`vllm/sampling_params.py:908`) calls
  `_validate_structured_outputs` (line 922).
- `_validate_structured_outputs` (line 1224) returns early when the config is
  `None` or the field is `None`. Otherwise it runs the diffusion and tokenizer
  checks, then reads `self.structured_outputs._backend` at line 1251. For a
  `str` this raises `AttributeError`.
- Later, `vllm/v1/structured_output/__init__.py:142` reads
  `structured_outputs._backend` again and asserts it is not `None`. That path
  is reached only after validation succeeds, so the early check prevents it.

The HTTP entrypoints are not affected. `chat_completion/protocol.py:399` and
`completion/protocol.py:133` type the field as `StructuredOutputsParams | None`,
and pydantic produces the dataclass from JSON. Only the Python `SamplingParams`
API can receive a wrong type.

## Root cause

`verify()` assumes the field is a `StructuredOutputsParams` and does not
check. The check is missing at the point where the field is first used.

## Proposed behaviour

- Reject any non-`None`, non-`StructuredOutputsParams` value with
  `VLLMValidationError` (a `VLLMClientError`), so the HTTP layer maps it to 400
  (`vllm/entrypoints/serve/exception_handling/error_response.py:55`). This
  matches how other `SamplingParams` checks report errors.
- Message: `structured_outputs must be a StructuredOutputsParams instance or
  None; got <type>.` with `parameter="structured_outputs"`.
- The guard sits before the `structured_outputs_config is None` early return, so
  it runs on every `verify()` call, including engines without a config.
- `None` and valid `StructuredOutputsParams` behave as before.

## Test plan

Added to `tests/test_sampling_params.py` (CPU, no engine):

1. Parametrized rejection for `"json"`, `1`, `{"type": "object"}`, `["json"]`:
   `verify()` raises `VLLMValidationError` matching "must be a
   StructuredOutputsParams".
2. `structured_outputs=None` still verifies with a real
   `StructuredOutputsConfig()`.
3. A valid `StructuredOutputsParams` passes the guard. It then fails the next
   check (`requires a tokenizer`), which shows the guard did not fire.

Not yet covered: an end-to-end regression through `LLM` or `RemoteOpenAIServer`,
which `tests/AGENTS.md` asks for on user-visible fixes. The fail-before-fix run should be repeated on the base commit to confirm the test fails there.

## Risks

- Overlap with #66256. Two PRs for one bug would conflict, and only one should
  land.
- Duplicate-type objects (for example a `StructuredOutputsParams` loaded from a
  different module path) would fail `isinstance`. That is not a concern for
  in-tree usage.
- Using `verify()` as the only check means an invalid value is still stored on
  the object until a request is validated. #66256 would reject it earlier.
