# b12x Linear and MoE Backends

[b12x](https://pypi.org/project/b12x/) provides optional CUDA kernels for
NVIDIA SM120 and SM121 GPUs. Install the dependency with:

```bash
uv pip install "vllm[b12x]"
```

b12x linear kernels participate in automatic selection after established
optimized backends and before emulation. Select the linear and MoE backends
explicitly with:

```bash
vllm serve <model> \
    --linear-backend b12x \
    --moe-backend b12x
```

Only pass `--moe-backend b12x` for a compatible packed-weight MoE model. The
linear and MoE backends can be selected independently.

b12x uses MXFP8 activations by default for MXFP4 MoE and the checkpoint's
activation format for NVFP4 MoE. MXFP4 falls back to BF16 when its A8 path does
not support the model configuration. W4A8 MXFP4 layers with an intermediate size
of 64 modulo 128 use the native prepared execution path of FlashInfer. Set
`VLLM_B12X_MOE_FP4_FORCE_A16=1` to force BF16 activations for either FP4 weight
format.

## Compressed MXFP4 expert scales

Set `VLLM_B12X_MOE_MXFP4_CSF=1` with `--moe-backend b12x` to keep eligible
MXFP4 expert block scales in a compressed scale format (CSF) in GPU memory. This option is disabled by
default. It needs a b12x installation that exposes `Mxfp4CsfWeights`, such as
FlashInfer's experimental b12x package. An older standalone b12x package can
lack this API.

```bash
VLLM_B12X_MOE_MXFP4_CSF=1 vllm serve <MXFP4-model> --moe-backend b12x
```

Each tensor-parallel rank encodes its scales without loss after it loads its
shard. FlashInfer selects the scale representation from the weight geometry.
If the prepared execution plan supports inline decoding, the GEMM kernels read
the compressed scales directly. Other plans expand the scales of the routed
experts into shared buffers before the MoE call. vLLM prepares and caches this
selection before CUDA graph capture. Activation precision does not change.
The selected FlashInfer kernels set the GEMM layouts and intermediate rounding.

Compression reduces the resident scale memory for compressible checkpoints.
It adds encoding time at load. The compression ratio and the inference overhead
depend on the prepared representation and the batch shape. Inline storage can
be larger than the canonical compressed payload.

This path requires MXFP8 activations and gated experts. The hidden size must
be a multiple of 256 and at most 7936. The per-rank intermediate size must be a
multiple of 64 and at most 8128. Compact layouts (an intermediate size of 64
modulo 128) require SiLU and BF16 input and output. This feature requires a
FlashInfer version with the prepared execution API, such as the pinned
flashinfer-python 0.7.2.post1.

Other shapes keep uncompressed scales and emit a warning. BF16 activation
backends (including `VLLM_B12X_MOE_FP4_FORCE_A16=1`) and packages without the
CSF or prepared execution API do the same.

Resident CSF layers do not support weight reloading. Each distinct layer shape
keeps one uncompressed scale buffer. Layers of that shape share it during
execution. The b12x MoE backend does not support expert parallelism or
all-to-all kernels, so layers run one at a time and the shared buffer is safe.

The pinned FlashInfer expands the compressed scales of the routed experts
before each call. This can make throughput slightly lower. Newer FlashInfer
versions can read the compressed scales inline.

## Supported Configurations

| Backend | Supported configurations |
| ------- | ------------------------ |
| Linear | Per-tensor FP8, 128x128 block FP8, MXFP8, NVFP4 (including W4A16), MXFP4, IQ2_XS, IQ2_XXS, and Q8_0 |
| MoE | Tensor-parallel MXFP4 weights with BF16 or MXFP8 activations; NVFP4 weights with BF16, NVFP4, or MXFP8 activations; IQ2_XS, IQ2_XXS, and Q8_0 weights with BF16 activations |
| Embedding | Packed Q8_0 lookup with BF16 output |

The b12x MoE backend does not support expert parallelism, expert maps, EXL3, or NF3.

## ModelOpt block codecs

ModelOpt mixed-precision checkpoints select block codecs through the
`quantization_config.quantized_layers` entries in `config.json`. Each entry
declares `quant_algo`, `group_size`, `block_payload_bytes`, and `packing="ggml"`:

| `quant_algo` | `group_size` | `block_payload_bytes` |
| --- | --- | --- |
| `IQ2_XS` | 256 | 74 |
| `IQ2_XXS` | 256 | 66 |
| `Q8_0` | 32 | 34 |

Serialized matrices have uint8 shape `[N, K/group_size, block_payload_bytes]`.
Dense preparation rearranges the encoded blocks without expanding the matrix
to BF16. Routed experts use bias-free SiLU or non-gated ReLU²; tensor-parallel
shards must preserve whole blocks and satisfy the kernel's alignment constraints.
Only Q8_0 supports packed embedding lookup.

Quantized normalization weights and other packed vectors are not supported.
Store normalization weights as ordinary floating-point tensors and omit their
entries from `quantization_config.quantized_layers`.

Dense, embedding, and expert matrices remain packed. Their execution uses BF16
activations without activation quantization. Prepare the kernels and workspaces
before CUDA graph capture.
