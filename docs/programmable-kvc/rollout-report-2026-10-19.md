## 实现与检查范围

暂停开始时直接在 `tool_wait` 里附带预计剩余时间。
movement 在预计暂停短于最低窗口或观测到的存出加加载耗时时跳过往返，恢复信号也不补做被跳过的加载。
缺少预测的调用保留压力判断行为，显式 COPY/MOVE 的语义独立。
这是传输时间摊销启发式；尚未建立逐请求的 GPU 重算成本模型。

工具耗时估计按工具名称组合保存有界历史，使用已完成批次更新。
在线 verl 循环记录工具组合、预测和实际耗时；旧回放没有工具名称，使用标明来源的统一估计。
`--prediction-mode fixed` 和 `--oracle` 分别保留固定预测与已知未来的对照。

quota 在每次准入前复核当前空闲块和运行请求的增长需求，避免同轮请求重复使用一份容量快照。
缓存复用评分仍按观察周期计算，等待上限后的公平性回退仍保留。
首版候选需求使用观察值，可能偏保守；运行需求按当前分配状态复核。
V2 改为在调度器完成实际缓存查询后复核候选需求，直接复用查询结果及当前引用状态。

`--prefetch-on-admission` 启用按准入启动的策略 COPY。
存在排队需求时，调度器选中匹配的 session/内容后才启动准备，并等待发布；加载失败后继续普通查询和重算。
没有排队需求时仍可提前准备。已有显式命令、取消、reset 和所有 rank 完成检查继续生效。
此模式的客户端结果收集期限包含已配置的排队预算和预测窗口。

另修正信号路径的重复观察：短暂停的跳过决策、恢复和保留无需扫描全部请求及其缓存命中。
这类内置消费者只读取物理计数与当前时间，保留调度观察和到达/等待历史。
能修改评分的信号仍使评分缓存失效；自定义策略子类默认继续接收完整观察。

行为检查复用现有 prefix、scheduler 和 HTTP suite：保护短暂停内容、学习已完成传输成本、跨次准入的容量预算、
准备成功后的实际缓存查询、失败回退、结束清理，以及预测不依赖存出结果的提交时机。

## 执行边界

第一阶段六个相关 CPU 文件为 649 项通过，耗时 207.20 s；其后加入准入准备和工具估计，
针对性检查为 23 项通过，耗时 10.76 s。完整相关回归与最终代码检查另行记录。
冻结后的 prefix、scheduler 和 HTTP 完整文件为 478 项通过，耗时 146.42 s。
Python 3.12 全量类型检查通过；默认 hooks 的格式修正已纳入，提交时重跑。
首个实现提交为 `b6d7fefcac`。扩展至控制、索引、engine、HTTP、prefix/scheduler、
Mooncake、offloading、CPU manager/policies 与 tiering 的回归为 1,980 项通过，耗时 646.67 s。
削减信号扫描后，三个受影响文件重新完整运行，479 项通过，耗时 148.14 s；
Python 3.12 全量类型检查再次通过。这些检查有范围重叠，不相加作为独立覆盖数。
信号扫描优化提交为 `ec5b1adbcd`，此后用于主性能对照的代码冻结。
五个实际 GPU buffer/搬运文件为 56 项通过、1 项 ROCm 专用检查跳过，耗时 24.65 s。
所有自建回归与 lint 进程结束后才启动 `native-clean` 及后续普通计时。

`native-repeat/native-0` 与 CPU 回归和代码检查有时间重叠，保留为诊断轮。
它完成 256 条轨迹、920 次调用，耗时 1,995.20 s，输入/输出长度指纹匹配；
GPU 归属审计发现额外进程 `3168596` 的 CUDA 上下文，matrix 因此保持失败，第二个原定重复未启动。
该失败触发前置队列检查中止；修订队列先等待独立 GPU 验证完成，再从 `native-clean` 启动。
后续无并行检查的普通计时轮作为主要对照；GPU 独占审计不能排除 CPU 干扰。
当前没有本轮优化后的完整吞吐结果，不能将历史 quota 收益归因于本轮修改。
