# RTX 6000D projection dispatch

`KernelConfig.enable_rtx6000d_bf16` opts into a bounded CuTe BF16 projection
path. It requires the NVIDIA RTX 6000D SKU with compute capability 12.0 and
156 SMs, CuTe DSL, contiguous BF16 weights, and no bias. It is disabled by
default and in batch-invariant mode.

```bash
vllm serve MODEL --kernel-config '{"enable_rtx6000d_bf16": true}'
```

Eligible layer suffixes are `q_b_proj`, `o_proj`, `in_proj_qkvgfab`, and
`eh_proj`. Eligible `(N, K)` weight shapes are `(4096, 1536)`, `(4096, 4096)`,
`(4096, 2048)`, `(6288, 4096)`, and `(4096, 8192)`. Only 2D inputs with one to
four rows use CuTe; other inputs use the existing torch linear operation.
Explicit FlashInfer BF16 backend choices take precedence over this option.
All four small row counts are compiled during weight preparation, using the
same non-PDL kernel instance used during inference.

This adapts the public [Pro6000d-community integration](https://github.com/PacoZhou1/Pro6000d-community)
and reuses vLLM's existing arithmetic kernel. Historical measurements from
that project apply to its locked deployment, not to arbitrary current vLLM
models or combinations of optimization settings. Validate correctness and
end-to-end performance on the intended model before enabling the option.
